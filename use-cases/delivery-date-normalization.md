# Delivery Date Normalization

## สถานะหลักฐาน

**[VERIFIED REAL PROJECT]** — ใช้กับ Field `Delivery Date` ในโปรเจกต์ OCR Sale Order และทดสอบตามรูปแบบวันที่ที่ระบุใน Use Case นี้แล้ว

## วัตถุประสงค์

แปลงค่าที่ OCR อ่านได้จากรูปแบบภาษาอังกฤษ เช่น `Friday, July 10, 2026` ให้เป็นรูปแบบ `10.7.2026` เพื่อให้เป็นรูปแบบเดียวกันก่อนส่งข้อมูลไปใช้งานต่อ

## เงื่อนไขการทำงาน

1. อ่านค่าจาก Field ชื่อ `Delivery Date`
2. ถ้าค่าเป็นรูปแบบ `d.m.yyyy` หรือ `dd.mm.yyyy` อยู่แล้ว จะไม่แก้ไขค่าเดิม
3. ถ้ายังไม่ใช่รูปแบบดังกล่าว จะตัดข้อความก่อน comma เฉพาะเมื่อคำแรกเป็นชื่อวันภาษาอังกฤษ
4. แยกชื่อเดือน วันที่ และปี
5. แปลงชื่อเดือนภาษาอังกฤษเป็นเลขเดือน
6. เขียนค่าที่แปลงแล้วกลับเข้า Field เดิม

## Rule Configuration Requirements

- ต้องใช้กับ Advanced Script Rule ที่สามารถแก้ไขค่า `.Value` ของ Field ได้ตามรูปแบบที่ยืนยันใน Repository
- ชื่อ Field ต้องตรงกับ `Delivery Date` รวมช่องว่างและตัวพิมพ์ใหญ่–เล็ก
- ควรตรวจสอบชนิดข้อมูลของ Field และผลลัพธ์ที่ระบบปลายทางต้องการก่อนนำไปใช้จริง

## ข้อจำกัดและความเสี่ยง

- รองรับรูปแบบ `Friday, July 10, 2026` และ `June 29, 2026`
- ยังไม่ครอบคลุมรูปแบบ `10 July 2026`, `July 10 2026` หรือรูปแบบวันที่ที่ OCR อ่านผิด
- Script ไม่ตรวจสอบความถูกต้องของวันตามปฏิทิน เช่น `31.2.2026`
- การส่งต่อไป SAP/RPA ต้องตรวจสอบ Data Type และรูปแบบวันที่กับ Contract ของระบบปลายทางแยกต่างหาก

## Runtime Error ที่พบและการแก้ไข

พบข้อความ `Cannot read property 'Value' of null` เมื่อ Rule เรียก `Context.GetField("Delivery Date")` แล้วไม่พบ Field ที่อ้างอิงได้ สคริปต์จึงตรวจสอบ Field ก่อนอ่าน `.Value` และตั้ง `Context.CheckSucceeded` กับ `Context.ErrorMessage` เมื่อไม่พบ Field

การแก้ไขนี้เป็นการป้องกัน Runtime Error ในระดับ Script เท่านั้น ต้องตรวจสอบชื่อ Field, full path และการเปิดสิทธิ์ Field ใน Edit Rule ให้ตรงกับเอกสารจริงด้วย
